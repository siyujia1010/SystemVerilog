# rand 与 randc：区别与"用 rand 实现 randc"

> 来源：dv笔记中"Randc（Random Cyclic）的原理与实现"一节的讲解整理。

## 1. rand 和 randc 的区别

以一个 2 位变量为例，它只能取 0、1、2、3 这 4 个值。

### 1.1 rand：像掷骰子

每次 `randomize()` 都独立重新掷一次，跟上一次的结果无关。连续随机 8 次可能得到：

```
2, 0, 2, 2, 3, 1, 0, 2
```

值可以重复，4 次之内也不保证 0~3 都出现过。

### 1.2 randc：像抽扑克牌不放回

4 张牌（0、1、2、3）洗好后一张张抽，**这 4 张抽完之前不会重复**；抽完后把牌收回重新洗，开始下一轮。连续随机 8 次可能是：

```
第一轮: 2, 0, 3, 1   ← 4 个值各出现一次，不重复
第二轮: 1, 3, 0, 2   ← 重新洗牌后的新顺序
```

每 4 次一组，组内 0~3 各出现恰好一次。c 就是 cyclic（循环）。

> 细节：两轮交界处可能挨着重复（第一轮最后是 1，第二轮第一个也可能是 1）。"不重复"只保证在**同一轮之内**。

## 2. 笔记中的三个要点

### 2.1 特点

> 优先选择从未被随机化过的值，直到所有值都出现过才重复。

即上面的"不放回抽牌"。好处是用最少次数把所有取值遍历一遍（2 位变量只需 4 次）；用 rand 想碰巧把 4 个值都碰到，平均要多跑好几次。

### 2.2 实际评价：工程中很少用，但面试常考

原因在代价上：

- **需要记住已用过的值**：仿真器要为 randc 变量保存一份"本轮已用清单"。2 位变量只需记 4 个值；32 位变量理论上要跟踪 2³²（40 多亿）个值，内存和速度都受不了，所以很多仿真工具会**限制 randc 变量的位宽**。
- **会影响其他变量的分布**：求解器会**先解 randc 变量、再解 rand 变量**，相当于隐式加了一条 `solve ... before`。与它有约束关系的 rand 变量的概率分布会被间接改变（即 solve before 效应），在做 cross coverage、希望几个变量各自独立随机时会带来干扰。

> 笔记原文写"增加编译器负担"，更准确地说是增加**仿真器 / 约束求解器**的负担。

### 2.3 面试考点：如何用 rand 实现 randc

不允许使用 `randc` 关键字，用普通 `rand` 加额外代码做出"一轮内不重复"的效果。有两种方法，见第 3、4 节。

## 3. 方法 1：记录已用值 + 约束排除（常用）

**思路**：维护一张"已用值"清单，随机时用约束排除清单里的值，随机完把新值加进清单；清单满了就清空，开始新一轮。

```systemverilog
class my_randc;
  rand bit [1:0] val;
  bit [1:0] used[$];                 // 这一轮已经用过的值

  // 约束：新值不能是清单里已有的
  constraint c_not_used { !(val inside {used}); }

  // randomize() 成功后自动调用
  function void post_randomize();
    used.push_back(val);             // 把这次的值记进清单
    if (used.size() == 4)            // 4 个值全用过了（2 位变量共 4 种取值）
      used.delete();                 // 清空，开始下一轮
  endfunction
endclass
```

### 3.1 执行过程

| 第几次 | 随机前 used | 约束允许的值 | 随机结果 | 随机后 used |
|---|---|---|---|---|
| 1 | 空 | 0,1,2,3 | 2 | {2} |
| 2 | {2} | 0,1,3 | 0 | {2,0} |
| 3 | {2,0} | 1,3 | 3 | {2,0,3} |
| 4 | {2,0,3} | 1 | 1 | 满了 → 清空 |
| 5 | 空 | 0,1,2,3 | …… | 新一轮开始 |

### 3.2 关键点

- `post_randomize()` 是 SV 内建回调：每次 `randomize()` **成功之后自动调用**，不需要手动调。对应还有 `pre_randomize()`，在随机**之前**自动调用。
- 这种方法仍走 `randomize()` 那一套，**能跟其他约束一起用**（比如再加 `val != 3` 照样正常工作），所以是常用做法。

> Mehta：`post_randomize()` 见 13.7.1 Pre-randomization and Post-randomization；`inside` 见 12.14 "inside" Operator。

## 4. 方法 2：洗牌 + 指针（暴力）

**思路**：不用约束求解器。把所有可能的值放进数组，用 `shuffle()` 打乱，用指针从头往后依次取；取到末尾说明一轮结束，重新 shuffle、指针归零。

```systemverilog
class my_randc2;
  bit [1:0] pool[$];                 // 所有可能的值
  int ptr;                           // 下一个要取的位置

  function new();
    for (int i = 0; i < 4; i++) pool.push_back(i);   // pool = {0,1,2,3}
    pool.shuffle();                  // 打乱，比如变成 {2,0,3,1}
    ptr = 0;
  endfunction

  function bit [1:0] next();
    if (ptr == pool.size()) begin    // 这一轮取完了
      pool.shuffle();                // 重新洗牌
      ptr = 0;                       // 指针回到开头
    end
    return pool[ptr++];              // 取出当前值，指针后移一位
  endfunction
endclass
```

这就是字面意义上的"抽扑克牌"：`shuffle()` 是洗牌，指针是"抽到第几张了"。

叫它"暴力"是因为：

- 要把所有可能的值**提前全部存进数组**，取值范围一大就很占内存；
- 完全绕开 `randomize()`，**没法跟其他约束配合**。

> Mehta：`shuffle()` 见 3.5.2 Array Ordering Methods。

## 5. 两种方法对比

| | 方法 1：记录 + 约束 | 方法 2：洗牌 + 指针 |
|---|---|---|
| 核心手段 | `inside` 约束排除已用值，`post_randomize` 记录 | `shuffle()` 打乱，指针依次取 |
| 是否用 `randomize()` | 是 | 否 |
| 能否跟其他约束配合 | 能 | 不能 |
| 内存开销 | 只存本轮已用的值 | 一次性存下所有可能的值 |
| 适合场景 | 一般情况，面试首选回答 | 取值范围很小、逻辑简单时 |
