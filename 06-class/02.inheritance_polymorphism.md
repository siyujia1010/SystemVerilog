# 继承与多态：extends、super、virtual、$cast

本篇统一用下面这组父类 / 子类（和笔记原文里的 `Packet` / `BadPacket` 对应）：

```systemverilog
class Packet;                              // 父类
  int packet_id;

  function new(int id);
    packet_id = id;
  endfunction

  virtual function void compute_crc();     // virtual 方法：父类句柄调用时，看实际 object 的类型
    $display("Packet::compute_crc");
  endfunction

  function void show_type();               // 非 virtual 方法：父类句柄调用时，看句柄自己的类型
    $display("Packet::show_type");
  endfunction
endclass

class BadPacket extends Packet;            // 子类：继承 Packet 的 packet_id、compute_crc()、show_type()
  bit error;                               // 子类新增的成员

  function new(int id);
    super.new(id);                         // 先调用父类构造函数，初始化继承来的 packet_id
  endfunction

  virtual function void compute_crc();     // 重写（override）父类的 virtual 方法
    $display("BadPacket::compute_crc");
  endfunction

  function void show_type();               // 同名的非 virtual 方法
    $display("BadPacket::show_type");
  endfunction
endclass
```

## 1. 继承：`extends`

`BadPacket extends Packet` 表示 BadPacket 是 Packet 的子类、Packet 是 BadPacket 的父类。**子类 = 父类已有的成员 + 子类新增的成员**：

```text
Packet（父类）
├── packet_id
├── compute_crc()
└── show_type()
       ^
       | extends
       |
BadPacket（子类）
├── 继承 packet_id、compute_crc()、show_type()
└── 新增 error
```

> Mehta：8.2 Base Class；8.3 Extended Class and Inheritance。

## 2. `super`：访问父类

```systemverilog
function new(int id);
  super.new(id);         // super.new()：调用父类的构造函数
endfunction

// 子类构造函数也可以多带自己的参数，比如 new(int id, bit err)：先 super.new(id)，再 error = err
```

```text
this.xxx  -> 当前 object 的成员
super.xxx -> 父类的成员
```

`super` 也能在子类里访问父类的同名成员和方法：

```systemverilog
class Parent;
  int value = 3;
  function int calc();
    return value * value;                        // 父类 calc() = 3 * 3 = 9
  endfunction
endclass

class Child extends Parent;
  int value = 2;                                 // 和父类同名的成员
  function int calc();
    return super.calc() + value * super.value;   // super.calc() = 9，value = 子类的 2，super.value = 父类的 3 → 9 + 2*3 = 15
  endfunction
endclass
```

> Mehta：8.3 Extended Class and Inheritance；8.4 Class Constructor。

## 3. 父类句柄指向子类对象（向上转型）

```systemverilog
Packet    pkt;
BadPacket badPkt1;

badPkt1 = new(1);
pkt = badPkt1;           // 子类 object 交给父类句柄：合法，因为 BadPacket 也是一种 Packet（upcasting，向上转型）
                         // 没有 new，不复制 object：pkt 和 badPkt1 指向同一个 BadPacket object

pkt.packet_id;           // 可以：Packet 里声明了 packet_id
pkt.error;               // 编译错误：虽然实际 object 是 BadPacket，但 pkt 的声明类型是 Packet，Packet 里没有 error
```

**成员变量能不能访问、访问的是哪个类的，先看句柄的声明类型。**

> Mehta：8.11 Upcasting and Downcasting。

## 4. 父子类同名成员

```systemverilog
// 这一节是单独的例子，这里的 Packet 和本篇开头的 Packet 无关
class Packet;
  int i = 1;
  function int get();
    return i;
  endfunction
endclass

class LinkedPacket extends Packet;
  int i = 2;               // 和父类同名的成员
  function int get();      // 和父类同名的方法，没有 virtual
    return -i;
  endfunction
endclass

LinkedPacket lp = new;
Packet p = lp;             // 父类句柄指向子类 object

p.i;                       // = 1：成员看句柄类型，访问的是父类的 i
p.get();                   // = 1：get() 不是 virtual，也按句柄类型调用父类的 get()
```

在子类内部，可以用 `super.i`、`super.get()` 明确指定父类的成员。如果方法声明成 `virtual`，第二行的结果就会变——见下一节。

## 5. `virtual` 与多态

```systemverilog
BadPacket badPkt1 = new(1);
Packet    pkt     = badPkt1;

pkt.compute_crc();       // 打印 BadPacket::compute_crc：compute_crc() 是 virtual，看实际 object 的类型（BadPacket）
pkt.show_type();         // 打印 Packet::show_type：show_type() 不是 virtual，看句柄的声明类型（Packet）
```

父类句柄调用 virtual 方法时，根据运行时实际 object 的类型决定执行哪个版本，这就是**运行时多态**。

```text
访问成员变量        → 看句柄的声明类型
调用 virtual 方法   → 看实际 object 的类型
调用非 virtual 方法 → 看句柄的声明类型
```

> Mehta：8.12 Polymorphism；8.13 Virtual Methods, Pure Virtual Methods, and Virtual Classes。

## 6. `$cast`：父类句柄转回子类句柄（向下转型）

父类句柄可能指向各种不同的子类 object，所以不能直接赋给子类句柄：

```systemverilog
Packet    pkt;
BadPacket badPkt2;

badPkt2 = pkt;                       // 编译错误：不允许把父类句柄直接赋给子类句柄
```

要用 `$cast` 在运行时检查 `pkt` 实际指向的是不是 `BadPacket`（或它的子类）：

```systemverilog
void'($cast(badPkt2, pkt));          // 笔记原文的写法：void' 把 $cast 的返回值丢掉，转换失败也不会知道

if ($cast(badPkt2, pkt))             // 推荐写法：检查返回值，成功返回 1、失败返回 0
  $display("cast success");
else
  $display("cast failed");

if (!$cast(badPkt2, pkt))            // 也常写成失败时直接报错
  $error("cast failed");
```

转换成功后，`badPkt2` 拿到的还是同一个 object 的句柄，不会复制 object：

```text
badPkt1 ──┐
pkt ──────┼──→ 同一个 BadPacket object
badPkt2 ──┘
```

> Mehta：8.11 Upcasting and Downcasting；`$cast` 的一般用法见 2.14 Dynamic Casting。

## 7. 笔记原文：把上面串起来

```systemverilog
Packet pkt;
BadPacket badPkt1, badPkt2;
badPkt1 = new(1);                // BadPacket 的构造函数只收一个参数 id（见本篇开头的类定义）
pkt = badPkt1;
//子类->父类
//对于属性的访问，使用什么类型的句柄就访问的是哪个class中的属性
//对于方法的访问，如果使用了 virtual 父类句柄使用的是子类方法，否则访问的是父类方法
void'($cast(badPkt2, pkt));
//父类->子类(父类保证实质上是一个子类)
pkt.compute_crc();               // compute_crc() 是 virtual，pkt 实际指向 BadPacket → BadPacket::compute_crc
badPkt2.compute_crc();           // badPkt2 本身就是 BadPacket 句柄 → BadPacket::compute_crc
```

## 8. 完整可运行代码

```systemverilog
class Packet;
  int packet_id;

  function new(int id);
    packet_id = id;
  endfunction

  virtual function void compute_crc();
    $display("Packet::compute_crc, packet_id = %0d", packet_id);
  endfunction

  function void show_type();
    $display("Packet::show_type");
  endfunction
endclass

class BadPacket extends Packet;
  bit error;                                   // 默认值 0

  function new(int id);
    super.new(id);
  endfunction

  virtual function void compute_crc();
    $display("BadPacket::compute_crc, packet_id = %0d, error = %0d", packet_id, error);
  endfunction

  function void show_type();
    $display("BadPacket::show_type");
  endfunction
endclass

module tb;
  Packet    pkt;
  BadPacket badPkt1;
  BadPacket badPkt2;

  initial begin
    badPkt1 = new(1);                          // 创建子类 object
    pkt = badPkt1;                             // 子类 object 交给父类句柄

    $display("--- Virtual method ---");
    pkt.compute_crc();

    $display("--- Non-virtual method ---");
    pkt.show_type();

    $display("--- Downcast using $cast ---");
    if ($cast(badPkt2, pkt)) begin
      $display("$cast success");
      badPkt2.compute_crc();
      badPkt2.show_type();
    end
    else
      $display("$cast failed");

    badPkt2.error = 1;                         // 通过 badPkt2 改 error
    $display("badPkt1.error = %0d", badPkt1.error);   // badPkt1 看到的也是 1：三个句柄指向同一个 object
    $finish;
  end
endmodule
```

输出：

```text
--- Virtual method ---
BadPacket::compute_crc, packet_id = 1, error = 0
--- Non-virtual method ---
Packet::show_type
--- Downcast using $cast ---
$cast success
BadPacket::compute_crc, packet_id = 1, error = 0
BadPacket::show_type
badPkt1.error = 1
```

## 9. 虚类与纯虚方法

> 这一节的例子都用"动物"来讲（Mehta 书里的原例子是 `BaseClass` / `ChildClass`，结构一样，这里换成了更好懂的猫狗）。

### 9.1 为什么需要 virtual class

先想一个问题：世界上有没有一只叫"动物"的动物？没有——只有具体的狗、猫、鸟。"动物"只是一个**概念**：它规定了"动物都会叫、都会吃东西"，但具体怎么叫、怎么吃，要由具体的动物自己决定。

这就是 **virtual class（虚类，也叫抽象类）**：基类只负责定义"子类都要有哪些方法"这套共同接口，本身是不完整的，永远不会被单独创建；各个子类再把细节补全。

```systemverilog
virtual class Animal;                        // virtual class：「动物」只是个概念，不能直接创建出一只"动物"
  pure virtual function void speak();        // 纯虚方法：规定"动物都会叫"，但只写原型，怎么叫由子类决定
endclass

class Dog extends Animal;
  virtual function void speak();             // 子类必须把 speak 实现出来
    $display("汪汪");
  endfunction
endclass

class Cat extends Animal;
  virtual function void speak();
    $display("喵喵");
  endfunction
endclass
```

### 9.2 规则

- virtual class **不能实例化**（不能 `new`），只能被继承。
- 但可以**声明 virtual class 类型的句柄**，并让它指向子类 object（就是上面讲的向上转型）。
- 必须由**非 virtual 的子类**把实现补全，才能创建 object。
- **纯虚方法**（`pure virtual`）只能声明在 virtual class 里，而且**只能是原型，不能有方法体**。
- virtual class 里的方法**默认不是 virtual**，要用的话必须显式写 `virtual`。

```systemverilog
Animal a;                // 声明 virtual class 类型的句柄：合法
a = new();               // 编译错误：virtual class 不能实例化（报 "An abstract class cannot be instantiated"）——不存在一只单纯的"动物"

Dog d = new();           // 正确：Dog 是具体的子类
a = d;                   // 正确：动物句柄指向一只狗（向上转型）
a.speak();               // 打印 汪汪：看实际 object 是 Dog
```

### 9.3 一个 virtual class 里可以有三种方法

```systemverilog
virtual class Animal;
  pure virtual function void speak();        // ① 纯虚方法：只有原型，子类必须实现（每种动物叫声不同）
  virtual function void eat();               // ② virtual 方法：有默认实现，子类可以重写（多态）
    $display("Animal: 吃东西");
  endfunction
  function void sleep();                     // ③ 普通方法：有方法体，不是 virtual
    $display("Animal: 睡觉");
  endfunction
endclass

class Dog extends Animal;
  function void speak();                     // 必须实现：speak 在 virtual class 里是 pure virtual
    $display("Dog: 汪汪");
  endfunction
  function void eat();                       // 重写 virtual 方法
    $display("Dog: 啃骨头");
  endfunction
  function void sleep();                     // 同名但父类的 sleep 不是 virtual，所以通过动物句柄调用时不会用到它
    $display("Dog: 趴着睡");
  endfunction
endclass

module tb;
  Animal a;
  Dog    d;
  initial begin
    // a = new;                              // 编译错误：不能实例化 virtual class
    d = new;
    a = d;                                   // 向上转型：动物句柄指向一只狗
    a.speak;                                 // 纯虚方法：打印 Dog 的实现
    a.eat;                                   // virtual 方法：看实际 object，打印 Dog 的版本
    a.sleep;                                 // 非 virtual 方法：看句柄类型，打印 Animal 的版本
  end
endmodule
```

输出：

```text
Dog: 汪汪
Dog: 啃骨头
Animal: 睡觉
```

两个常见的编译错误：

```systemverilog
class Animal;                                // 把 virtual class 改成普通 class
  pure virtual function void speak();        // 编译错误：纯虚方法不能出现在非抽象类里
endclass

virtual class Animal;
  pure virtual function void speak();
endclass
class Fish extends Animal;                   // 非 virtual 的子类，没有实现 speak
endclass                                     // 编译错误："Virtual method 'speak' not implemented in class 'Fish'"
```

virtual class 不是只能放纯虚方法，上面例子里就同时有三种。但最常见的做法是把方法都声明成 `pure virtual`：这样既禁止基类被单独实例化，又强制每个子类都必须提供实现。

### 9.4 多层继承：中间的 virtual class 可以不实现

```systemverilog
virtual class Animal;
  pure virtual function void speak();
endclass

virtual class Pet extends Animal;            // 中间这一层也是 virtual class（"宠物"也只是个概念）：可以不实现 speak
endclass

class Dog extends Pet;                       // 第一个非 virtual 的子类：必须实现 speak
  function void speak();
    $display("汪汪");
  endfunction
endclass
```

规则是：**只要子类还是 virtual class，就不必实现纯虚方法；第一个非 virtual 的子类必须补全**。如果中间的 virtual class 已经给了方法体，后面的非 virtual 类就不用再实现：

```systemverilog
virtual class Pet extends Animal;
  virtual function void speak();             // 中间层已经给出默认叫声
    $display("嗷");
  endfunction
endclass

class Hamster extends Pet;                   // 从 Pet 派生（不是直接从 Animal），speak 已有实现，这里可以不写
endclass
```

### 9.5 virtual class 与 UVM

virtual class 常用来做类库的基础：定义好共同的接口，各个独立来源的类模型都按这套接口接进来。UVM 采用的就是这种方法（Mehta 书里提到这一点；UVM 源码里的 `uvm_object`、`uvm_component` 就是 virtual class，所以不能直接 `new` 它们，只能用派生类）。

注意区分两个容易混的概念：**virtual class**（整个类是抽象的，不能实例化）和 **virtual 方法**（决定父类句柄调用时看实际 object，§5 讲的多态）。一个普通的非抽象 class 里也可以有 virtual 方法。

> Mehta：8.13.2 Virtual (Abstract) Class and Pure Virtual Method；8.13 Virtual Methods, Pure Virtual Methods, and Virtual Classes。

## 10. UVM 中的 class

UVM 里的 driver、monitor、agent、transaction、sequence 本质上都是 SystemVerilog class，上面讲的继承、`super.new()`、`::` 都会直接用到。

### 10.1 `super.new(name, parent)`

```systemverilog
class my_driver extends uvm_driver #(my_transaction);   // 继承 UVM 的 uvm_driver
  function new(string name = "my_driver",
               uvm_component parent = null);
    super.new(name, parent);     // 调用 uvm_driver（往上是 uvm_component）的构造函数，让 UVM 记下组件的名字和父子层级
  endfunction
endclass
```

### 10.2 `new()` 与 factory 的 `create()`

```systemverilog
tr = new();                                       // 普通 SV 写法：直接创建固定类型的 object
tr = my_transaction::type_id::create("tr");       // UVM 推荐写法：先经过 factory，可以被 override 替换成别的类型
```

`my_transaction::type_id::create` 从左往右读：`my_transaction` 这个类 → 它注册 factory 时生成的 `type_id` 包装器 → 包装器的 `create` 方法。

`create()` 不是不执行 `new()`：它是先由 factory 决定最终要创建哪个类型，再调用那个类型的构造函数。

### 10.3 sequence item 也是 class

```systemverilog
class my_transaction extends uvm_sequence_item;   // 定义类 + 继承
  rand bit [7:0] data;                            // rand 随机成员
  rand bit [7:0] addr;

  `uvm_object_utils(my_transaction)               // 注册进 factory

  function new(string name = "my_transaction");   // 构造函数（object 只有 name 一个参数，component 才是 name + parent）
    super.new(name);                              // 调用父类构造函数
  endfunction
endclass
```

> 这部分是 UVM 内容，Mehta 这本 SystemVerilog 书不涉及。

## 11. 易错点

1. **以为父类句柄指向子类 object 就创建了新 object**：`pkt = badPkt1;` 没有 `new`，还是同一个 object。
2. **以为父类句柄能访问子类新增成员**：`pkt.error` 会编译错误，成员能否访问看句柄的声明类型。
3. **父类方法忘了声明 `virtual`**：想让父类句柄调用到子类重写的方法，父类里的方法必须是 `virtual`。
4. **`this` 和 `super` 混淆**：`this` 是当前 object，`super` 是父类。
5. **向下转型不检查 `$cast` 的结果**：不要默认父类句柄一定指向目标子类，用 `if ($cast(...))` 或 `if (!$cast(...)) $error(...)` 检查。
6. **把 virtual class 和 virtual 方法混为一谈**：前者是整个类抽象、不能 `new`；后者是方法按实际 object 类型调用。virtual class 里的方法默认也不是 virtual。
7. **非 virtual 的子类忘了实现纯虚方法**：编译会报错；只有仍是 virtual class 的子类才可以不实现。

## 12. 面试问答

- **继承用什么关键字？** `extends`；子类继承父类成员，并可以增加自己的成员。
- **`super` 是什么？** 用来访问父类成员，比如 `super.new()` 调用父类构造函数。
- **父类句柄能指向子类 object 吗？** 可以（向上转型）；但通过父类句柄直接可见的成员受父类类型限制。
- **什么是多态？** 父类句柄指向子类 object，调用 `virtual` 方法时根据实际 object 类型执行对应子类的版本。
- **为什么需要 `$cast`？** 父类句柄转成子类句柄有类型风险，`$cast` 在运行时检查实际 object 是否属于目标子类。
- **什么是 virtual class（抽象类）？** 只用来定义共同接口、不能实例化的类，必须由非 virtual 的子类补全实现后才能创建 object；里面可以有 `pure virtual` 方法，只有原型、子类必须实现。
- **pure virtual 方法有什么要求？** 只能声明在 virtual class 里，只能是原型不能有方法体，第一个非 virtual 的子类必须实现它。

## 13. 整章知识树与口诀

```text
SystemVerilog Class
├── class / object / handle      class 是模板，new() 创建 object，handle 指向 object
├── constructor new() / this     初始化成员；this 指当前 object
├── static                       普通成员每个 object 一份，static 整个 class 一份
├── 封装 local / protected       控制类外、子类能否访问
├── 赋值与拷贝
│   ├── p2 = p1                  句柄赋值，全部共享
│   ├── p2 = new p1              浅拷贝，外层独立、内部共享
│   └── p2 = p1.copy()           深拷贝，全部独立
├── package / scope              A::B 去 A 的域里找 B
├── 继承 extends / super         子类 = 父类成员 + 新增成员
├── 父类句柄 → 子类 object       成员看句柄类型
├── virtual / 多态               virtual 方法看实际 object 类型
├── $cast                        父类句柄安全转回子类句柄
└── virtual class / pure virtual 只定义接口，子类实现
```

```text
Class 是模板，Object 是实体；
Handle 找对象，new 才创建；
this 找自己，super 找父类；
普通成员各自有，static 全班共一份；
直接赋值共对象，浅拷贝共内层，深拷贝全独立；
extends 做继承，父句柄能指子对象；
成员看句柄，virtual 看对象，下转要 $cast；
A::B 就是去 A 的域里找 B。
```
